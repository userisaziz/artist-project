How a stranger becomes
a verified artist on your platform

This is the complete first-impression journey of the GetReady app: signing in with just a phone number, choosing a side of the marketplace, and — for artists — building a profile that your admin team approves before it goes live. Written in plain language first; the full technical flow is at the bottom for your engineers.

No passwords, ever Sign-up = sign-in Every artist is reviewed Progress is never lost
PART 1 · SIGN-IN

Four taps to get in. There is no account to create.

The user types their phone number, receives a 6-digit code by SMS, and they're in. If the number is new, the account is created silently at that very moment — nobody ever fills a registration form.

STEP 1

Enter phone number

The country code is pre-filled for India. The button stays disabled until the number is valid — bad input never reaches the server.

STEP 2

A code arrives by SMS

Six digits, valid for 5 minutes. The phone's autofill suggests it instantly under Android & iOS.

STEP 3

Six boxes, one glance

The app submits the moment the sixth digit lands. A wrong code shakes the boxes gently — the user retries in place.

STEP 4

They're in. Stay in.

The app remembers the session for a week — closing and reopening never asks for the code again, and the session repairs itself invisibly.

The clever part: to a stranger and a returning user the screens look exactly the same. Nobody can tell which numbers have accounts — and nobody needs to "register" first.

PART 2 · ONBOARDING

One question splits the marketplace in two

Right after the first sign-in the app asks for a name, then "What brings you here?" — clients book artists, creators offer services. The answer is remembered; roles can be switched anytime from the profile.

The client's path

Two taps, then browsing

≈ 30 SECONDS

Enters their name (email optional)

Taps "Book an artist"

Immediately browsing artists near them — no further gates

The artist's path

Five short steps, then your review

5 STEPS
1

Profile — business name, city, up to 6 categories, avatar photo

2

Location — a real neighbourhood chosen from our list + PIN code

3

Services — picks from your catalog and sets their own prices & durations

4

Portfolio — at least 6 photos of real work; the first becomes the cover

5

Identity — Aadhaar number + both sides of the card, then Submit for review

An admin approves (or rejects with a reason) before the artist appears in the directory. Quality control stays in your hands.

Every step saves instantly to the server — quit halfway, reopen next week, the app resumes at exactly the right step.

Photos go straight to secure cloud storage, never through the app server — uploads stay fast and cheap at any scale.

The ID document is stored in a private vault. The artist's own screen later shows only the last 4 digits of the number. Nothing else is ever displayed.

PART 3 · WHY IT'S SAFE

Quiet protection at every step

Codes expire in 5 minutes and each one works only once — a stolen screenshot is worthless.

5 wrong guesses lock the code. Brute-forcing a 6-digit code by trial is mathematically shut down.

SMS spending is capped per number and per device, so nobody can burn your SMS budget by spamming requests.

The server answers identically whether the number exists or not — your user list can't be probed from outside.

Sessions rotate their keys constantly; a replayed key kills the whole stolen session and logs the thief out.

Code guesses, sign-ins, delivery failures and ID reveals are all written to an audit trail you can inspect.

Sign-in & session

sequenceDiagram
    autonumber
    participant U as User
    participant A as App
    participant B as Backend
    participant S as SMS
    U->>A: phone number
    A->>B: POST /auth/otp/request
    B->>B: rate limits and 60s cooldown
    B->>S: send 6 digit code
    B-->>A: 204 always - same for new and known numbers
    U->>A: types the code
    A->>B: POST /auth/otp/verify
    B->>B: check hash - consume code - JIT create user if new
    B-->>A: 200 access token 15 min and refresh token 7 days
    A->>B: GET /users/me with bearer token
    B-->>A: 401 when access token expires
    A->>B: POST /auth/refresh
    B-->>A: 200 fresh pair - old token rotated

Onboarding & artist review

sequenceDiagram
    autonumber

    A->>C: PUT image directly to the bucket
    A->>B: POST /artists/me/photos with the key
    A->>B: PUT /artists/me/kyc step 5 - private bucket
    A->>B: POST /artists/me/submit

Artist profile lifecycle — the admin's control panel drives this
