# React Native Library Stack (mobile/)

Curated against [jondot/awesome-react-native](https://github.com/jondot/awesome-react-native)
(commit `6733606`) and [reactnative.directory](https://reactnative.directory), then filtered to
what this app actually needs. The approved table is
[LIBRARIES.md](./LIBRARIES.md).

`.qoder/rules/react-bulletproof.md` is the hard law (layering, naming, one API client, TanStack
Query as the only server cache, tokens only, `expo-secure-store` for secrets). Where a rule and
this skill disagree, the rule wins.

## Decision ladder — run in order, stop at the first hit

1. **React Native built-in.** `FlatList`, `Modal`, `KeyboardAvoidingView`, `Alert`, `Share`,
   `PanResponder`. Already covers most of this app. Not `Animated`: animation goes through
   `src/core/motion` (Reanimated 4), never the legacy API.
2. **An Expo SDK module already in `mobile/package.json`.** 16 of the 29 dependencies are Expo
   modules — `expo-image`, `expo-image-picker`, `expo-image-manipulator`, `expo-linear-gradient`,
   `expo-location`, `expo-notifications`, `expo-secure-store`, `expo-splash-screen`,
   `expo-updates`, `expo-font`, `expo-asset`, `expo-haptics`… Check there before proposing anything new.
3. **An existing wrapper in `mobile/src/components/common/`.** Sheets, OTP input, photo,
   skeletons, pressable feedback, screens, chips and maps are already wrapped there and
   token-driven (`BottomSheet.tsx`, `OtpInput.tsx`, `Photo.tsx`, `PinMap.tsx`,
   `PressableScale.tsx`, `Skeleton.tsx`, `StateViews.tsx`, `Screen.tsx`, `MotionEntrance.tsx`).
   Extend it; do not bolt a second kit next to it. Motion has the same rule in a sharper form:
   only `src/core/motion` (`motion.ts`, `haptics.ts`) and the shared primitives (`AppButton`,
   `PressableFeedback`, `Skeleton`, `MotionEntrance`, `Crossfade`, `BottomSheet`, `OtpInput`)
   import `react-native-reanimated` — screens and features go through those, and new motion code
   should keep that boundary. The legacy RN `Animated` API is retired (0 files).
4. **A row in [LIBRARIES.md](./LIBRARIES.md)** marked `candidate`. That is the pre-approved pick
   for the capability — install it, do not re-survey the ecosystem.
5. **Only then** propose a new dependency, and record it in LIBRARIES.md **and** in
   `.qoder/rules/react-bulletproof.md` §11 in the same change. If a second kit for the same
   capability would be needed, the answer is *no* — pick one and note the rejected alternative.

## Adding a dependency

```bash
cd mobile
npx expo install <pkg>          # never bare `npm i` for anything with native code
npx expo install --check        # no NEW lag; baseline as of 2026-10-31 is 7 patch-level lags
npx expo prebuild --platform android --no-install   # only if the package needs native config
```

Native-config changes belong in `mobile/app.json` `plugins` (with a permission string that
names the feature), not in generated native code — `mobile/android/` is gitignored and
regenerated by prebuild.

### Two consequences to state before installing

- **Native code breaks the OTA path.** `app.json` uses `runtimeVersion: { policy: "fingerprint" }`
  with `expo-updates`, so a new or bumped native module changes the fingerprint and needs a fresh
  EAS build (`npx eas build -p android --profile preview`); `eas update` alone will not reach
  testers. JS-only packages are OTA-safe.
- **New Architecture compatibility.** This app runs RN 0.86 on the New Architecture with
  `reactCompiler: true`. Confirm the library is listed as supported at reactnative.directory
  before adding it; old modules that only ship the legacy architecture are a no.

### Paired versions

- `react-native-reanimated` 4.x requires a matching `react-native-worklets` — install both with
  `npx expo install` so SDK 57 picks the pair (currently `4.5.1` + `0.10.1`).
- `react-native-gesture-handler` must resolve to exactly one copy; if it enters the tree, check
  `npx expo install --check` and dedupe any nested version.
- Icons stay `lucide-react-native`; `react-native-vector-icons` is not additive, it is a rival.
- **Hermes V1 floor:** SDK 55–56 and `expo@57.0.8` or below carry a Hermes V1 memory regression
  that bites hard when `react-native-worklets` / `react-native-reanimated` are in the tree (they
  are). Never downgrade `expo` below `57.0.9`; keeping it at the SDK 57 table head is the fix.

### Tests must keep running headless

Every native module needs a jest mock or `jest.config.js` transform, or the suite dies at import.
House pattern (`jest-expo` 57, RNTL 14 — `render()` is async, use `screen.*`):

```ts
jest.mock('expo-image', () => ({ Image: require('react-native').View }));
```

Prefer named `mock`-prefixed bindings inside a hoisted factory; never reach for real native
timers or devices in unit tests.

## Gates before finishing in `mobile/`

```bash
cd mobile && npm run lint && npx jest   # expo lint incl. eslint-plugin-boundaries
```

Plus `npx expo install --check` whenever `package.json` changed. Pre-existing boundary
violations are `warn` backlog — do not add new ones (no feature→feature imports; `app/` is
assembled, never imported).

## Known gaps worth acting on

Ranked by user-visible payoff; details and install commands in [LIBRARIES.md](./LIBRARIES.md).

1. **Forms** — closed 2026-10-31: `react-hook-form` 7 + `@hookform/resolvers` 6 + `zod` 4 are installed,
   and every screen's rules are now a schema in `src/utils/<feature>/*-draft.ts` (quotes, service price
   and extras, shop product and delivery, saved addresses, checkout, new post, travel radius). Two ways
   to consume one schema, per rules §7: submit-driven (`useForm` + `zodResolver`) and live-gated
   (`firstIssue`). What is left is not drift, it is parsing: `EditAccountForm` composes the shared
   `readDateOfBirth` and one server-conflict message, and the checkout's payment picker is a cross-object
   choice, not a field rule.
2. **Long lists** — closed 2026-10-31: the 15 paginated catalogs (feed / explore / shop / bookings /
   inbox …) run on `@shopify/flash-list` 2.0.2; short static lists and `ChatThread.tsx` (v2 has no
   `inverted`) stay on `FlatList`. Jest needs the hand-rolled mock in `jest-setup.ts` — the official
   `jestSetup` shipped broken in 2.0.2.
3. **Gestures + haptics** — haptics closed 2026-10-31: `expo-haptics` is installed and reached only
   through `src/core/motion/haptics.ts` (`haptic('tap' | 'select' | 'success' | 'warning' | 'error')`),
   opted in per control with `PressableFeedback haptic=` — today `AppButton` (tap), `Chip` and
   `Segmented` (select), `OtpInput` (error); it is mocked in `jest-setup.ts`. Motion is closed too: all
   three legacy `Animated` files (`BottomSheet`, `OtpInput`, `HomeHero`) now run on Reanimated 4, with
   `Crossfade` as the new primitive. **Still open: `react-native-gesture-handler`**, without which
   drag-to-dismiss on `BottomSheet.tsx` (today `Modal` + `timings.sheet`) is out of reach.
4. **Keyboard** — closed for consistency 2026-10-31, open for the library: all 10 `KeyboardAvoidingView`
   sites now go through `components/common/KeyboardAvoider.tsx`, and ESLint refuses a raw one outside it.
   The wrapper pads on **both** native platforms: edge-to-edge Android (the SDK 57 default) no longer
   shrinks the window for the IME, so `adjustResize` alone leaves the form footer behind the keyboard —
   that regression shipped on 2026-10-31 and is fixed in `KeyboardAvoider`. `react-native-keyboard-controller`
   remains the curated equaliser if RN's post-animation measurement still isn't enough on device.
5. **Date/time pickers** — no picker dependency; schedules, working hours and slots are custom.
6. **Transient feedback** — no toast layer at all (0 toast usages, `Alert` in 12 files).
7. **Connectivity and crash visibility** — no `@react-native-community/netinfo`, no Sentry; the
   login flow already has to guess between 5xx and network-timeout failure classes.

Do not bundle these into one change. One capability per commit, dependency and all.

## Which Expo skill to load

Routing and header/tab questions → `expo-router`. Native controls, media, safe areas →
`expo-native-ui`. Motion and gesture work → `expo-animation`. Token/component structure →
`expo-design-system`. API calls and states → `expo-data-fetching`. SDK bumps → `expo-upgrade`.
OTA publishing and channel/runtime debugging → `eas-update`. Store and APK builds →
`eas-app-stores`.
